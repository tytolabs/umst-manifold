# Golden gate fixtures (researcher path)

Copy-paste guide for **external researchers and agents** who need to replay manifold gate parity locally — no Lean checkout, no prototype tree, no network.

**Crate root:**

```bash
cd /path/to/umst-manifold
```

**Toolchain:** `rust-toolchain.toml` pins **1.88** (`rustup toolchain install 1.88`).

**Related:** full feature matrix in [`VERIFY.md`](VERIFY.md); gate architecture in [`GateUnificationSpec.md`](GateUnificationSpec.md) and [`PROTOTYPE_GATE_MAP.md`](PROTOTYPE_GATE_MAP.md).

---

## What these fixtures prove

| Fixture | Test target | Witness |
|---------|-------------|---------|
| Hand-built bulk transitions | `tests/gate_parity_fixture.rs` | `ThermodynamicTransitionEvaluator` + `ThermodynamicMixEvaluator` agree on three verdict classes |
| Vendored adversarial pack | `tests/gate_adversarial.rs` | **FNR = 0** and **FPR = 0** on 75 pinned cases (`tests/data/adversarial_gate_test.json`) |
| Kleisli + registry | `tests/gate_kleisli.rs` | `umst.gate.kleisli_unit` catalog surface + composition chain |
| CBF dual-run | `tests/gate_cbf_parity.rs` | Transition gate vs `ThermodynamicCBF` scalar lane |
| JSON dual-run | `tests/gate_dual_run_parity.rs` | `tests/data/gate_dual_run_fixtures.json` |
| Reject catalog IDs | `tests/gate_reject_catalog_id.rs` | Unknown / malformed `catalog_id` paths |

All of the above run with **default features** except `gate_server_http` (needs `gate-server-bin`).

## 1. Gate parity golden (`gate_parity_fixture`)

[`tests/gate_parity_fixture.rs`](../tests/gate_parity_fixture.rs) pins **hand-constructed** [`ThermodynamicState`](../src/gate/thermo_transition.rs) pairs. No JSON files — states are built in Rust so the test stays deterministic and offline.

### Run

```bash
cargo test --test gate_parity_fixture
```

Verbose (see individual case names):

```bash
cargo test --test gate_parity_fixture -- --nocapture
```

### Golden vectors and expected verdicts

| Helper | Scenario | Expected [`AdmissibilityVerdict`](../src/gate/verdict.rs) | Wire token (`as_str()`) |
|--------|----------|-----------------------------------------------------------|-------------------------|
| `golden_identity_admissible()` | Identical bulk state over `dt = 1 s` ⇒ zero intrinsic dissipation | `Accepted` | `ACCEPTED` |
| `golden_mass_reject()` | `\|Δρ\| = 120` kg/m³ (bound is `< 100`) | `MassViolation` | `MASS_VIOLATION` |
| `golden_negative_dissipation_reject()` | Free-energy spike breaks Clausius–Duhem (`D_int ≥ −tolerance`) | `NegativeDissipation` | `NEGATIVE_DISSIPATION` |

Each vector is exercised twice:

1. **Host transition path** — `ThermodynamicTransitionEvaluator::check_transition_host` → `TransitionVerdict` mapped to `AdmissibilityVerdict`.
2. **Mix evaluator path** — `ThermodynamicMixEvaluator::evaluate_thermo_transition` on [`ThermodynamicStateSnapshot`](../src/gate/mix_eval_registry.rs).

Catalog surfaces are also pinned:

- `umst.gate.cd_transition` / `clausius_duhem_transition`
- `thermodynamic_mix` / `thermodynamic_mix_transition`

### Interpreting failures

| Symptom | Likely cause |
|---------|----------------|
| `MassViolation` vs `Accepted` flip on identity case | Mass bound or `dt` scaling changed in `ThermodynamicGate` |
| Mix path differs from host path | Snapshot mapping (`host_to_snapshot`) or mix filter predicate drift |
| `catalog_id` assertion failure | Registry rename — update golden + [`GateUnificationSpec.md`](GateUnificationSpec.md) |

## 2. Adversarial golden (`gate_adversarial`)

[`tests/gate_adversarial.rs`](../tests/gate_adversarial.rs) loads a **vendored** JSON witness at [`tests/data/adversarial_gate_test.json`](../tests/data/adversarial_gate_test.json). The file was generated by prototype **Experiment E6** (`umst-prototype_2/scripts/test_gate_adversarial.py`) and checked into manifold so CI and external replay do not need the prototype tree.

### Run

```bash
cargo test --test gate_adversarial
```

### Hard safety contract

The test asserts:

- `summary.false_negatives == 0` (**FNR** — unsafe mix admitted)
- `summary.false_positives == 0` (**FPR** — safe mix rejected)
- `cases.len() == summary.total_test_cases` (currently **75**)
- Every case has `false_negative: false` and `false_positive: false`

Pinned summary (do not relax without re-running E6):

```json
{
  "total_test_cases": 75,
  "false_negatives": 0,
  "false_positives": 0,
  "n_unsafe_cases": 42,
  "n_safe_cases": 33
}
```

### Case fields (for manual inspection)

Each row in `cases[]` includes:

| Field | Meaning |
|-------|---------|
| `task_id` | Scenario family (e.g. `T3-A`, `T3-B`) |
| `test_label` | Sub-case (`well_below_floor`, `exact_floor`, …) |
| `predicted` | Model strength (MPa) |
| `expected_admit` | Ground-truth admissibility |
| `gate_admitted` | Gate outcome at replay time |
| `gate_reason` | Human-readable reject string (e.g. `C1: f28=39.9 < required=40.0 MPa`) |
| `false_negative` / `false_positive` | Must stay `false` in the golden file |

Example reject line (safe to cite in papers / agent traces):

```
C1: f28=39.9 < required=40.0 MPa (gap=0.1)
```

### Optional: regenerate from prototype (maintainers)

If you have `umst-prototype_2` as a sibling:

```bash
export UMST_PROTOTYPE_ROOT=../umst-prototype_2
python3 "${UMST_PROTOTYPE_ROOT}/scripts/test_gate_adversarial.py"
# writes results/adversarial_gate_test.json — copy into tests/data/ only after FNR/FPR review
```

`scripts/verify_umst_stack.sh` runs the Python script when present, then the Rust golden test. Set `UMST_REQUIRE_ADVERSARIAL_GATE=1` to fail closed if the prototype script is missing (see [`VERIFY.md`](VERIFY.md) §5.1.1).

## 3. Full gate parity bundle (recommended)

Single command matching `scripts/verify_umst_stack.sh` gate block:

```bash
cargo test --test gate_parity_fixture \
  --test gate_kleisli --test gate_cbf_parity \
  --test gate_dual_run_parity --test gate_reject_catalog_id \
  --test gate_adversarial
```

From a **multi-repo workspace** root:

```bash
cargo test -p umst-manifold --manifest-path umst-manifold/Cargo.toml \
  --test gate_parity_fixture --test gate_kleisli --test gate_cbf_parity \
  --test gate_dual_run_parity --test gate_reject_catalog_id \
  --test gate_adversarial
```

Stack verify (formal export + bidirectional catalog when sibling formal is present):

```bash
export UMST_REQUIRE_FORMAL_EXPORT=1
export UMST_FORMAL_ROOT=../umst-formal-double-slit   # optional
bash scripts/verify_umst_stack.sh
```

Agent-layer golden mixes live in **`umst-concrete-cartridge`** (`phase8_adversarial` integration test). That path covers MCP-boundary mix JSON and `explain: true` samples — complementary to manifold's vendored E6 JSON.

cd ../umst-concrete-cartridge

## 6. Updating golden files

| Artifact | When to change | Review bar |
|----------|----------------|------------|
| `gate_parity_fixture.rs` helpers | Thermodynamic bound or verdict mapping changes | Both evaluator paths must agree; update [`GateUnificationSpec.md`](GateUnificationSpec.md) if `catalog_id` moves |
| `tests/data/adversarial_gate_test.json` | New E6 run after gate logic change | **FNR must stay 0**; document delta in CHANGELOG |
| `tests/data/gate_dual_run_fixtures.json` | Dual-run policy change | Pair with `gate_dual_run_parity` green |

Never commit a golden refresh that increases `false_negatives` — that is a hard safety regression (R1/R3 witness ladder).
